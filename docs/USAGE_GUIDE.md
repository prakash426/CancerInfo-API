# CancerInfo API Multi-Language Usage Guide

Client examples for CancerInfo API in several languages. The examples call the hosted service at `https://cancerinfo-api.onrender.com`; replace the base URL with `http://localhost:3000` to work against a local server. The examples do not certify clinical content or marketplace gateway behavior.

## Current integration rules

For RapidAPI subscription allowances, request limits and platform charges, see [Hosted API access and usage](ACCESS_AND_USAGE.md). Check the published Pricing tab before using the service.

Use `https://cancerinfo-api.onrender.com` for the hosted service or `http://localhost:3000` for a local server. A freshly bootstrapped development database keeps unreviewed content private, so most content routes return empty lists locally until reviewed records are loaded. `/docs`, `/redoc` and `/openapi.json` are generated by FastAPI. The root path serves HTML unless Accept explicitly requests JSON without text/html.

Handle non-2xx responses before reading data, empty arrays before indexing, null source dates, pagination and per-record jurisdiction. A country filter also includes GLOBAL records; do not label every returned record as country-specific. Present sources alongside each record and do not treat the code’s license_status as independent approval.

Most public routes use `data` and `meta`, sometimes with pagination. Health uses a direct object. Validation errors use the API's `error.code`, `error.message` and `error.details` envelope. Search returns `data.results` with cancer matches and optional content records or consensus items. `GET /v1/facts?ids=...` returns a direct `data` array of the same result items for saved citation revalidation; unknown or withdrawn IDs are omitted. JavaScript is a valid external client language; it is not a Node backend dependency. Marketplace headers must come from the actual listing configuration.

## 1. cURL / Shell

```bash
# Get symptoms with fact-level provenance
curl -X GET "https://cancerinfo-api.onrender.com/v1/cancers/breast-cancer/symptoms?country=US" \
  -H "Accept: application/json"

# Copy an ID from a search result's record.id or consensus_item.id
curl 'https://cancerinfo-api.onrender.com/v1/facts?ids=47567f24-2d21-4ab3-929b-6fc95ccfe758'
```

## 2. Python (requests & httpx)

```python
import requests

BASE_URL = "https://cancerinfo-api.onrender.com/v1"

# 1. Search for a cancer or abbreviation
response = requests.get(f"{BASE_URL}/search", params={"q": "CRC"}, timeout=20)
response.raise_for_status()
data = response.json()
for match in data["data"]["results"]:
    print("Matched Cancer:", match["cancer"]["canonical_name"])

# 2. Fetch country-specific symptoms with source citations
records_res = requests.get(
    f"{BASE_URL}/cancers/ovarian-cancer/symptoms",
    params={"country": "GB"}, timeout=20
)
records_res.raise_for_status()
records_data = records_res.json()
records = records_data["data"]["records"]

for rec in records:
    print("\n--- Record ---")
    print(rec["content"])
    for citation in rec["sources"]:
        print("Source:", citation["organization"])
        print("Source URL:", citation["url"])
```

## 3. TypeScript / Node.js (fetch)

```typescript
interface CancerResponse {
  data: {
    cancer: {
      canonical_name: string;
      slug: string;
    };
    records: Array<{
      content: string;
      sources: Array<{
        organization: string;
        url: string;
        attribution_text: string;
      }>;
    }>;
  };
}

async function getCancerSymptoms(slug: string, country: string = "US"): Promise<void> {
  const url = `https://cancerinfo-api.onrender.com/v1/cancers/${slug}/symptoms?country=${country}`;
  
  const res = await fetch(url, {
    headers: { "Accept": "application/json" }
  });
  
  if (!res.ok) {
    throw new Error(`API Error: ${res.statusText}`);
  }
  
  const data: CancerResponse = await res.json();
  console.log(`Cancer: ${data.data.cancer.canonical_name}`);
  
  data.data.records.forEach((record, index) => {
    console.log(`\n[Record ${index + 1}]: ${record.content}`);
    console.log(`Citation: ${record.sources[0]?.organization} (${record.sources[0]?.url})`);
  });
}

getCancerSymptoms("breast-cancer", "US");
```

## 4. Go

```go
package main

import (
	"encoding/json"
	"fmt"
	"io"
	"net/http"
)

type HealthResponse struct {
	Status    string `json:"status"`
	ApiName   string `json:"api_name"`
	Database  string `json:"database"`
}

func main() {
	resp, err := http.Get("https://cancerinfo-api.onrender.com/v1/health")
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()

	body, _ := io.ReadAll(resp.Body)
	var health HealthResponse
	json.Unmarshal(body, &health)

	fmt.Printf("API Name: %s\nStatus: %s\nDatabase: %s\n", health.ApiName, health.Status, health.Database)
}
```

## 6. iOS (Swift / URLSession)

```swift
import Foundation

struct CancerSource: Codable {
    let organization: String
    let url: String
}

struct CancerRecord: Codable {
    let content: String
    let sources: [CancerSource]
}

func fetchCancerSymptoms(cancer: String) async throws {
    let url = URL(string: "https://cancerinfo-api.onrender.com/v1/cancers/\(cancer)/symptoms?country=US")!
    let (data, _) = try await URLSession.shared.data(from: url)
    print("Received payload: \(data.count) bytes")
}
```

## Example limits

Kotlin requires an application-defined CancerKnowledgeResponse model and configured Retrofit base URL. Swift illustrates transport only; add status validation and decode the documented envelope before displaying content. The Go example needs timeout, status and decoding-error handling for a production client. These snippets are not independently tested SDKs. Preserve country context, missing dates, attribution and empty coverage in every integration.
